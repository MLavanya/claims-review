# AI development notes

- Codex inspected an empty repository and proposed the initial architecture. The user approved the stack but reworked important details: the agent reducer must not own reviewer decisions; field versions must drive stale-decision detection; reviewed-status semantics must be documented as an assumption; citation offsets should be derived; and confidence movement must be visible. Those corrections are reflected in the final plan before application code was written.
- Accepted as-is: the proposed React + TypeScript + Vite frontend, small Express/SSE backend, plain CSS, Vitest/Supertest testing stack, and feature-local reducer approach were approved because they are proportional to the exercise and keep the frontend/backend boundary explainable.
- These notes will only record interactions that actually occur. No second rejected/reworked output has occurred yet.
- Reworked during verification: after the project folder was renamed, Codex's patch helper still targeted the original working path and recreated it. Typecheck exposed the mismatch because npm could not see the project scripts. The generated files were moved into the real `claims-review` Git repository, the accidental empty folder was removed, and verification was restarted from the correct path.
- Manual testing found that an intentional SSE close after `run_finished` was reported as a connection interruption, producing contradictory success and error messages. Terminal events are now recorded before the stream is closed; only a disconnect before `run_finished` or `run_failed` reports a transport error.
- Manual testing also found that the first responsive layout was not adequate at mobile width despite responsive behaviour being required. The layout now stacks below tablet width, uses a single-column queue on phones, removes rigid minimum widths, wraps evidence and long values, and stacks controls at phone width.
- A second manual device test showed that the responsive correction still rendered the desktop shell at an emulated 430px width. The exact cause was a missing viewport meta declaration: mobile Chrome used a desktop-sized layout viewport, so the media queries did not activate. The viewport is now declared explicitly, allowing the existing tablet and phone breakpoints to produce a genuine single-column layout.
- Manual testing started from an already-failed claim: one click on “Replay failed run,” followed by confirmation, did not restart the failed scenario correctly, while “Replay normal run” did work. The client used one mutable EventSource ref in every stream callback, so a late callback from the previous terminal stream could close or hydrate over the newly connected stream. Each replay now has a connection generation; stale callbacks are ignored and terminal handlers close only their own EventSource instance.
- Manual phone testing showed that stacking the entire queue above the review would not scale as the queue grows. As a product-design choice—not a MarvelX-specified navigation pattern—the phone layout now presents either the queue or the selected review, with a real “Back to claims” button. Both remain mounted, so navigating between these views does not reset an active run, partial output, or reviewer decisions; desktop keeps the split layout.
- A focused application-level regression test now replaces an active EventSource and invokes the retained terminal and error callbacks from the old source. It verifies that those stale callbacks cannot close or corrupt the current run or add a false connection error.
